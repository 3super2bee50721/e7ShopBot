# 秘密商店自动化助手

基于屏幕截图与 OpenCV 模板匹配的桌面自动化脚本，用于在游戏「秘密商店」界面中识别 **圣约书签**、**神秘奖牌**，自动点击购买与刷新，并通过 Tkinter 小窗口显示刷新次数、购买组数和估算出现概率。

主程序：[`1.py`](1.py)

> 本工具会控制鼠标并截取屏幕，仅适合在你自己的电脑、自己的游戏客户端上使用。使用前请确认游戏与平台的用户协议是否允许此类辅助。分辨率后需要重新截取模板图片。

## 功能

- 窗口截图 + 灰度模板匹配，查找书签 / 奖牌图标
- 校验道具名称文字，并区分可购买（`1/1`）与已购买（`0/1`）
- 点击购买按钮并等待确认弹窗
- 当前页未命中目标时滚动一次再扫；仍没有则点击刷新并确认
- 达到设定的最大刷新次数后自动停止
- GUI：开始 / 停止、实时统计、运行状态
- 操作记录写入 `purchase_log.txt`

## 运行环境

- Windows（脚本使用 `PIL.ImageGrab` 与 `pyautogui` 桌面控制）
- Python 3（建议 3.10+）
- 游戏窗口尽量全屏或固定位置；脚本启动后会点击固定坐标 `(1455, 700)` 尝试激活窗口，请按你的屏幕改这个值

## 安装

```bash
cd d:\py\gc\shuashuqian
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
```

依赖见 [`requirements.txt`](requirements.txt)：`opencv-python`、`numpy`、`Pillow`、`pyautogui`。Tkinter 一般随 Python 安装，无需单独 pip。

## 模板图片

程序从 `./templates/` 读取灰度 PNG。启动时若某张读失败，会弹出「模板缺失」警告且无法开始。

| 文件名 | 用途 |
|--------|------|
| `saint_bookmark.png` | 圣约书签图标 |
| `mystic_medal.png` | 神秘奖牌图标 |
| `bookmark_text.png` | 书签名称文字 |
| `medal_text.png` | 奖牌名称文字 |
| `buy_btn.png` | 购买按钮（当前购买逻辑主要用坐标偏移，仍需加载） |
| `confirm_buy.png` | 购买确认弹窗 |
| `refresh_btn.png` | 刷新按钮 |
| `confirm_refresh.png` | 刷新确认弹窗 |
| `available.png` | 可购买状态（如 `1/1`） |
| `unavailable.png` | 已购买状态（如 `0/1`） |

截图建议：

1. 游戏界面缩放到你平时使用的分辨率
2. 只截目标本身，尽量少带背景
3. 与实际游戏画面缩放一致；匹配阈值默认 `CONFIDENCE = 0.85`

更改分辨率后需要重新截图，不更改的话不需要。

## 使用方法

1. 打开游戏并进入秘密商店，保证商店界面可见
2. 运行：

   ```bash
   python 1.py
   ```

3. 在窗口中填写 **最大刷新次数**（默认 100），点 **开始**
4. 脚本会先等待约 3 秒，再点跳出弹窗，点击确认后立即点击游戏窗口，然后进入扫描 → 购买 / 滚动 → 刷新循环
5. 需要中止时点 **停止**（当前这一轮点击可能会再跑一小段才完全停下）

运行时不要挡住游戏窗口，也不要把鼠标抢回去，否则点击会点偏。

## 界面说明

| 项 | 含义 |
|----|------|
| 已刷新 | 成功确认刷新的次数 |
| 圣约书签 / 神秘奖牌 | 成功走完购买确认的组数 |
| 书签概率 / 奖牌概率 | `(组数 / 刷新次数) /  * 100%`，仅供参考 |

## 关键配置（在 `1.py` 顶部）

| 常量 | 默认 | 说明 |
|------|------|------|
| `CONFIDENCE` | `0.85` | 模板匹配阈值 |
| `SCROLL_AMOUNT` | `300` | 向下滚动幅度 |
| `PRICE_BOOKMARK` / `PRICE_MEDAL` | `184000` / `280000` | 价格常量（当前逻辑未用于扣费判断） |
| `REFRESH_COST` | `3` | 刷新消耗（当前未参与控制流） |
| `DELAY_RANGE` | 若干区间 | 点击、滚动、循环间隔的随机延迟 |

购买前还有固定 `time.sleep(3)`；刷新确认超时最长约 12 秒。

## 工作流程（简图）

```
扫描当前可见区域 → 尝试购买
        ↓ 未买到
向下滚动再扫描 → 尝试购买
        ↓ 仍未买到
点击刷新 → 确认刷新 → 等待加载 → 再扫描两次
        ↓
刷新次数 ≥ 上限 或 用户停止 → 结束
```

单次购买：文字校验 → 状态为可购买 → 偏移点击 → 匹配并点击 `confirm_buy`。

## 日志

日志文件：`purchase_log.txt`（已在 `.gitignore` 中忽略）。内容包括扫描、购买成功/跳过、刷新次数和异常。

## 常见问题

**一点击就开始报模板缺失**  
检查 `templates/` 是否存在上表全部 PNG，路径相对运行时的当前工作目录。

**识别不到或乱点**  
分辨率、缩放、UI 皮肤与截图不一致。重新截模板，并调整 `CONFIDENCE`、购买偏移`。

**点了购买但没有确认**  
确认弹窗模板不对，或超时过短（`wait_and_click_template` 默认 3.5 秒）。
